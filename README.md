# Multimedia AI Content Detection

Detect whether **text, images, audio or video** were produced by a human or
generated by AI, behind a single Streamlit interface.

The project is built in weekly stages. **Weeks 1–3 are complete**: the
interface, the text detector and the image detector. Audio and video are
scheduled for weeks 4–6 and already appear in the UI as planned modalities.

## Results

Measured on held-out test splits the models never saw during training.
Reproduce with `python scripts/evaluate.py`.

| Modality | Test samples | Accuracy | F1 | ROC-AUC | False-positive rate |
|----------|-------------:|---------:|---:|--------:|--------------------:|
| Text  |  8,000 | 98.78% | 0.9877 | 0.9990 | 1.10% |
| Image | 10,000 | 96.81% | 0.9684 | 0.9958 | 3.98% |

**False-positive rate** is reported alongside accuracy on purpose: wrongly
flagging genuine human work as AI is the error that causes real harm, and a
headline accuracy figure hides it.

A test score alone is not evidence that a detector works — see
[the dataset trap](#the-dataset-trap-this-project-ran-into) below, where a
**99.51%** model turned out to be broken. `scripts/sanity_check.py` is the
second gate: hand-written passages that appear in no dataset.

```
  6/6 correct on hand-written text
  [PASS] informal diary note        P(AI)=0.000   [PASS] assistant-style explainer  P(AI)=0.910
  [PASS] formal history essay       P(AI)=0.003   [PASS] assistant-style listicle   P(AI)=0.533
  [PASS] technical explanation      P(AI)=0.001
  [PASS] conversational reply       P(AI)=0.000
```

Tests: `python -m unittest discover -s tests` — 31 tests, stdlib `unittest`, no
extra dependencies.

## Quick start

```bash
pip install -r requirements.txt
```

Then run the pipeline in order. Each step caches its output, so re-running is
cheap.

```bash
python scripts/prepare_text_data.py
python scripts/train_text.py
```

```bash
python scripts/prepare_image_data.py
python scripts/train_image.py
```

```bash
streamlit run app/streamlit_app.py
```

The app opens at <http://localhost:8501>. It also runs before the models are
trained — each panel tells you which command to run.

Two checks worth running after training:

```bash
python scripts/evaluate.py        # both models, held-out test splits
python scripts/sanity_check.py    # hand-written text the models never saw
```

Ready-made demo uploads (with their true labels in the filenames) are in
[`samples/`](samples/).

### Hardware

Training was done on an RTX 3050 laptop GPU (4 GB). The image model trains in a
few minutes there and still works on CPU, just slower. The text model is

### The dataset trap this project ran into

Worth reading before trusting any AI-text-detection benchmark, including this
one.

**Attempt 1 — "AI Vs Human Text" (Kaggle, 500k rows).** Trained, scored
**99.51% accuracy** with a 0.30% false-positive rate. It then labelled every
hand-written passage put to it — informal, formal, technical — as AI-generated
with ~100% confidence.

The cause: every document in that corpus, in *both* classes, has been lowercased
and **stripped of all punctuation**. The model had never seen a comma or a
capital letter. Real input sits so far outside the training distribution that
the stylometric features extrapolate wildly and the classifier saturates. The
sentence-based features were dead weight too — with no full stops, every
document is one "sentence", so burstiness was identically zero.

**Attempt 2 — HC3 raw.** Real punctuation, but a different trap: **88.5% of the
human answers are detokenised** (`"like this , here ."`) against 0.3% of the
ChatGPT answers. A classifier learns "space before a comma ⇒ human" and reports
~99% while learning nothing about writing.

**What is actually used.** HC3 with `normalise_text()` applied *identically to
both classes*, which repairs the detokenisation spacing. It is close to a no-op
on ChatGPT text and removes the giveaway from human text, so what remains is
genuine style. The prepare script prints an artefact report every run:

```
space-before-punct   human=0.000  ai=0.000      <- neutralised
has-uppercase        human=0.995  ai=1.000
has-apostrophe       human=0.774  ai=0.567      <- genuine: humans contract more
median length        human=725    ai=1025
```

Train/test is split **by question**, not by answer, so no paraphrase of a test
question is visible during training.

The honest takeaway: **the 99.5% was the broken model and the lower number is
the working one.** `scripts/sanity_check.py` exists because a test split cannot
catch this class of failure — it runs the detector over hand-written passages
that appear in no dataset.

### One label convention, enforced once

Throughout the project: **`1` = AI-generated, `0` = human / real.**

The two source datasets disagree with each other — the text dump uses
`generated=1` for AI, but CIFAKE uses `0=FAKE, 1=REAL`, which is inverted. The
flip happens in exactly one place (`src/mmdetect/data/image_data.py`) and is
guarded by assertions, because a silent mix-up here trains a model that is
confidently backwards while every metric still looks perfect.

## How each detector works

### Text — TF-IDF + stylometry → logistic regression

Three feature views feed one classifier:

- **Word TF-IDF** (1–2 grams) — vocabulary and phrasing.
- **Character TF-IDF** (3–5 grams, `char_wb`) — punctuation and morphology,
  robust to words the model has never seen.
- **24 stylometric features** — the ones that actually separate the classes:
  *burstiness* (spread of sentence length; humans vary a lot, LLM prose is
  metronomic), vocabulary richness, hapax ratio, punctuation habits, and
  surface noise like stray double spaces and ALL-CAPS.

**Every stylometric feature is scale-invariant, and that took two attempts.**
The first version included raw `n_chars` / `n_words` / `n_paragraphs` counts.
Because HC3's human answers are shorter than its ChatGPT answers (median 725 vs
1025 characters), the model learned *"short ⇒ human"* — it classified all four
hand-written human passages correctly, then read short AI-written passages as
human, showing `N Words = 80 → Human` as its top signal. Document length is a
property of the corpus and trivially changed, so it has no business being a
feature. Counts are gone; only rates (per 1000 characters) and ratios remain.

Two subtler versions of the same leak were caught by
`test_features_are_scale_invariant`:

- *type/token ratio* falls as a document grows, so vocabulary richness is
  measured on a fixed 50-word window. The window is set **below** the shortest
  admitted document rather than at a comfortable-looking 200, because most HC3
  answers are 120–180 words and a 200-word window would bind on almost none of
  them — letting length back in through the side door.
- *paragraphs per sentence* collapses to `1 / n_sentences` for any
  single-paragraph document, which is most of them. Replaced with a paragraph
  break **rate**.

Logistic regression is deliberate rather than lazy: it emits calibrated
probabilities (the UI shows a percentage, not just a label) and its coefficients
are readable, so the app can show **which** features drove each verdict instead
of asserting a number. That per-feature breakdown in the UI comes straight from
the model's own weights.

#### What it actually learned — and one artefact that survived

Readable coefficients mean the model can be audited, so here is that audit
(`reports/text/top_features.png`):

| Pushes toward **AI** | Pushes toward **human** |
|---|---|
| `\n`, `\n\n`, `.\n` — newline characters | `you`, `I`, `my`, `but`, `so`, `etc` |
| `important to`, `it is`, `such as`, `means that` | `"`, `*` — quoting and markup |
| | `displaystyle` |

Two of those three groups are genuine. The ChatGPT phrasings (*"it is important
to note"*, *"such as"*, *"means that"*) and the human personal register
(*you / I / my*) are real stylistic differences.

The other two are honest weaknesses:

- **Newlines are the single strongest AI signal**, because 30% of HC3's ChatGPT
  answers contain them against 2% of the human answers. That is partly real —
  chat models do produce numbered lists — and partly an artefact of how the
  human answers were scraped. It makes the model lean on formatting.
- **`displaystyle`** is LaTeX markup that leaked in from maths-heavy human
  answers. A pure scrape artefact with no stylistic meaning.

How much does the newline reliance matter? `scripts/sanity_check.py` collapses
all whitespace before predicting, so every passage it scores is newline-free —
and the model still gets **6/6**. It leans on newlines but does not depend on
them. Worth knowing before trusting a score on heavily formatted input.

### Image — compact CNN on CIFAKE

A VGG-style network over 32×32 inputs: three blocks of two 3×3 convolutions with
batch-norm, then global average pooling — about 296k parameters. Small kernels
at full resolution are what pick up the high-frequency fingerprints diffusion
models leave behind (upsampling artefacts, unnatural local noise).

Augmentation is deliberately mild — horizontal flip and a 4px shift only. Blur,
JPEG re-encoding or rescaling would destroy the very frequency-domain evidence
the model depends on.

**The honest part.** The model is trained on 32×32 images, but people upload
4000×3000 photos. A single downscale throws away most of the evidence, so
inference scores several *views* of an upload — the whole image resized to
32×32 (weighted highest, since that matches how CIFAKE was built), plus 32×32
tiles cut from a 96px-short-side version — and reports how much the views
agreed. Disagreement is surfaced as low confidence rather than hidden behind
one averaged number. This is a real domain shift: **accuracy on arbitrary web
images is materially lower than the CIFAKE test-set figure.**

## Limitations

These matter more than the accuracy numbers, and the app repeats them in-product
rather than burying them here.

- **A probability is not proof.** Scores near 50% mean the model genuinely
  cannot tell; the app labels those **Uncertain** instead of guessing.
- **Never use a score alone to accuse anyone.** Treat it as one weak signal.
- **Text**: trained on HC3 — English question-and-answer prose, with **ChatGPT
  as the only AI author**. Newer models, other languages, code, heavily edited
  AI text and short passages fall outside what it learned. Below ~50 words the
  style statistics are too noisy to trust, and the app says so.
- **Images**: CIFAKE is 32×32 CIFAR-10 photos against Stable Diffusion images.
  Detecting a 4K Midjourney render is a genuinely different problem.
- **Generators outpace detectors.** These numbers describe these datasets at
  this point in time, not the open web.
- **Both models are deliberately interpretable rather than maximal.** A
  fine-tuned transformer would score higher on text; it would also be slower,
  heavier and much harder to explain in a viva. That trade-off was chosen on
  purpose and is easy to revisit.
